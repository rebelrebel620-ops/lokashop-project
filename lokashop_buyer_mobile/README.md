# LokaShop — Buyer app (Flutter)

A native buyer app for LokaShop. It talks to the **same Laravel backend and
the same MySQL database** as the website — no separate data store, no mock
data. Everything a buyer can do on the site (browse, cart, checkout, track
orders, rate, message sellers, file complaints) is here.

This project only contains the buyer role. Seller/admin/logistics stay on
the website as before.

## 1. Set up the backend API first

The Flutter app needs the small JSON API that was added to your existing
Laravel project (`routes/api.php`, `app/Http/Controllers/Api/BuyerApiController.php`,
`app/Http/Middleware/ApiBuyerAuth.php`). That's a separate zip — unpack it
over your project (or merge the changed files in), then:

```bash
cd lokashop-ecommerce
composer install          # if not already
php artisan serve --host=0.0.0.0 --port=8000
```

`--host=0.0.0.0` matters — it lets your phone/emulator reach the server on
your machine's network, not just `localhost`.

## 2. Point the app at your server

Edit `lib/config.dart`:

```dart
const String apiBaseUrl = 'http://10.0.2.2:8000/api';
```

- Android emulator → `http://10.0.2.2:8000/api` (already set — 10.0.2.2 is
  the special alias the emulator uses for your host machine)
- iOS simulator → `http://127.0.0.1:8000/api`
- Physical phone on the same Wi-Fi → `http://<your-computer's-LAN-IP>:8000/api`
  (find it with `ipconfig` / `ifconfig`)
- A deployed server → `https://yourdomain.com/api`

## 3. Get a runnable Flutter project

This delivery contains `lib/`, `pubspec.yaml` and assets only — not the
generated native `android/` / `ios/` platform folders, since those need to
be generated by your local Flutter SDK. Two ways to get them:

**Option A — quickest**
```bash
flutter create lokashop_buyer
# then copy this project's lib/ and pubspec.yaml into it, overwriting the defaults
cd lokashop_buyer
flutter pub get
flutter run
```

**Option B — scaffold in place**
```bash
cd lokashop_buyer_app   # this folder
flutter create .
flutter pub get
flutter run
```

Either way, once `flutter pub get` succeeds you can run on an emulator,
simulator, or physical device with `flutter run`, or build a release with
`flutter build apk` / `flutter build ios`.

## Notes on how it maps to the backend

- **Auth**: the backend has no token system built in (it's session/cookie
  based for the website), so the API reuses the existing `remember_token`
  column on `users` as a simple bearer token — issued on `/api/login`,
  cleared on `/api/logout`. No new database migration was needed.
- **Registration still requires admin approval** and an ID document upload,
  exactly like the website — the register screen reflects that.
- **No product photos in the schema** — the backend never stored images, so
  product "photos" in the app are generated color gradients (seeded by
  product id/name) rather than broken image placeholders. Swap in real
  photos any time by adding an `image_url` style column + endpoint field
  and rendering `Image.network` in `ProductArt`.
- Cart, addresses, checkout, order tracking, ratings, messages, notifications
  and complaints all map 1:1 to the equivalent web routes/controller logic,
  just returning JSON instead of Blade views.
